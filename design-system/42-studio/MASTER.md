# 42 Studio — Design System (Master)

Source of truth for UI work in this repo. Generated by the `ui-ux-pro-max` skill
(v2.13.0, `--design-system --persist -p "42 Studio" --stack react`) and then
**reconciled with the system this app actually has**. The raw generator output is
kept beside this file as `MASTER.generated.md`.

## Why this file diverges from the generator

The skill answers "what should a greenfield product of this type look like?" It
recommended **Dark Mode (OLED)** on a `#020617` ground with Fira Code / Fira Sans.
42 Studio is not greenfield:

- The palette was **deliberately migrated to light**. `tailwind.config.ts:25-26`
  records it: the `bg.*` keys were kept only so classes would not break while the
  values were repointed to "the v1 white-on-near-black-text palette".
- `styles.css:7` pins `:root { color-scheme: light }` and there are **zero** `dark:`
  classes in 139 files.
- The owner's decision for this pass is **stay light-only**.

So the generator's palette, typography and mode recommendations are **not adopted**.
What IS adopted is everything the skill is actually authoritative on: the UX
guidelines, WCAG rules, anti-patterns and the pre-delivery checklist. Those are
stack- and brand-independent, and they are reproduced at the bottom of this file.

## Global rules

### Colour tokens (`frontend/tailwind.config.ts`)

| Role | Token | Hex |
|------|-------|-----|
| Page / surface | `bg.DEFAULT`, `bg.subtle` | `#FFFFFF` |
| Raised surface | `bg.muted` | `#F2F2F4` |
| Deep surface | `bg.deep` | `#FAFAF9` |
| Text | `fg` | `#0F1011` |
| Secondary text | `muted` | `#71717A` |
| Divider | `border.DEFAULT` / `border.strong` | `#E5E5E7` / `#D4D4D8` |
| Brand accent | `accent.DEFAULT` / `accent.hover` | `#06B6A2` / `#048876` |
| Success | `success` | `#10B981` (= `emerald-500`) |
| Warning | `warning` | `#F59E0B` (= `amber-500`) |
| Danger | `danger` | `#EF4444` |

**Contrast trap:** `text-success` (`#10B981`) on white is **2.56:1** and fails WCAG AA.
Existing `emerald-600`/`700` and `amber-600`/`700` uses are deliberate contrast fixes,
not drift. Do not "normalise" them to the token.

**Not drift, do not consolidate:** the raw violet / fuchsia / rose / cyan / teal / blue /
sky / orange / indigo / pink families encode **one hue per content type** in
`YasLibrary.tsx` (`TYPE_META`) and `pages/Assets.tsx` (`CATEGORIES`). A semantic token
cannot express "one hue per tool". Only exact `emerald-500` -> `success` and
`amber-500` -> `warning` are byte-identical renames.

### Typography

- **Sans:** Inter (400/500/600/700). **Mono:** JetBrains Mono (400/500) — `font-mono`
  is used 284 times; it is the label/eyebrow voice of the app, not just code.
- Semantic classes: `.h1`, `.h2`, `.lead`, `.eyebrow` (`styles.css:26-38`).
- Scale below `text-sm`: use `text-2xs` (11px) and `text-3xs` (10px). These are defined
  as **bare strings**, so they emit font-size only — byte-identical to the
  `text-[11px]` / `text-[10px]` literals they replace.
- Do **not** fold `text-[12px]` into `text-xs`: `text-xs` also sets
  `line-height: 1rem`, which is a silent layout change.

### Spacing, radius, shadow

- 4 / 8px rhythm. Page container: `max-w-7xl mx-auto px-6 md:px-10 py-8`, or full-bleed
  via `useFullBleed()` (`components/LayoutChrome.tsx`).
- `borderRadius.DEFAULT` is overridden to `0.5rem`, so bare `rounded` == `rounded-lg`.
  Cards use `rounded-xl`.
- `shadow-soft` (resting), `shadow-lift` (hover), `shadow-glow` (focus).

## Component vocabulary

The primitive layer is **CSS-first** in `frontend/src/styles.css` (`@layer components`),
with React primitives in `frontend/src/components/ui/`.

| Concern | Use | Never |
|---|---|---|
| Button | `.btn` + `.btn-primary` / `-accent` / `-ghost` / `-danger` / `-secondary`, sized with `.btn-xs` / `.btn-sm` | Appending bare `text-xs` to `.btn`; a bespoke button class string |
| Surface | `.card` (+ `.card-hover`) | Rebuilding it from `border border-border rounded-*` |
| Status chip | `.pill` + `.pill-*` | Ad-hoc `bg-X/10 text-X border border-X/20` |
| Field | `.input` / `.textarea`, or `ui/Field` | Hand-written input classes with no focus style |
| Dialog | `ui/Modal` (portal + focus trap + Escape + scroll lock) | Hand-rolled overlay; a non-portalled modal |
| Spinner | `ui/Spinner` | `border-2 border-current border-t-transparent animate-spin` |
| Job progress | `ui/JobProgress` | A `<style>` tag inside JSX |
| Empty / error | `ui/EmptyState` (`variant: 'card' \| 'inset'`), `ui/ErrorCard` | A bare `<p>No items yet.</p>` |
| Loading | `components/Skeleton.tsx` | Ad-hoc `animate-pulse` divs |
| Feedback | `useToast()` | `alert()` |
| Confirm | `useConfirm()` | `window.confirm()` |
| Icons | `lucide-react` | Inline hand-drawn SVG; Unicode glyphs as icons |
| Aspect ratio | `lib/aspect.ts` | Inline ternaries with differing fallbacks |
| Polling | `lib/usePoll` | A bare `setInterval` or an `await`-sleep loop |

**Modal standard:** one scrim (`bg-black/60`) and one z-index scale. The 6 scrim
opacities and 5 z-bands currently in the tree are fossils of the old dark theme.

## Project-specific invariants

These are not style preferences. Breaking them breaks the app.

1. **Modals must `createPortal(node, document.body)`.** A page-transition transform
   makes any non-portalled modal mis-position. `RunPanel` is the one documented
   exemption: it renders from `App.tsx` as a sibling of `<Layout>`, outside the
   transform.
2. **Tailwind class strings must be complete literals.** Never build a class name by
   concatenating fragments — the JIT will not emit it. Select whole literals by key.
   `components/trends/controls.tsx` documents and follows this.
3. **Flag-guarded files stay byte-stable.** `components/trends/featureFlags.ts` requires
   that flipping one constant is the entire revert, so `GeneralTrendsTab.tsx`,
   `GeneralTrendCard.tsx` and `ThemesTab.tsx` are excluded from every mechanical sweep.
4. **`isolatedModules: true`** — re-export types with `export type { ... }` or the
   build fails.
5. **No `<style>` tags inside JSX.** Keyframes belong in `tailwind.config.ts`.
6. **Never use `thumbnail_url` as a video `poster`.** The backend aliases it to
   `video_url` for comp-ready rows, so the image loader decodes a whole MP4 (measured
   29 MB). See `YasLibrary.tsx:654-658`.

## Anti-patterns (from the skill, and applicable here)

- Emojis as structural icons — use SVG (Lucide).
- Missing `cursor-pointer` on clickable elements.
- Layout-shifting hover/press transforms.
- Text below 4.5:1 contrast.
- Instant state changes — transitions belong in the 150-300ms band.
- Invisible focus states; `outline-none` with no replacement ring.
- Hidden error states; slow dashboards; decorative charts.

## Pre-delivery checklist

- [ ] No emojis used as icons; icons all from Lucide
- [ ] Body text contrast >= 4.5:1 (remember `text-success` on white is 2.56:1)
- [ ] Focus visible on every interactive control, including inside modals
- [ ] Focus is not obscured by sticky headers or overlays (WCAG 2.2 AA)
- [ ] `prefers-reduced-motion` respected — including the infinite animations
- [ ] Responsive at 375 / 768 / 1024 / 1440px; no horizontal scroll on mobile
- [ ] No content hidden behind fixed bars
- [ ] Dialogs: portal, focus trap, Escape, backdrop click, scroll lock, focus restore
- [ ] Async state announced (`aria-busy` / `aria-live`), including Suspense fallbacks
- [ ] `npm run typecheck && npm run build` both green
- [ ] `git diff --stat` empty for the three flag-guarded files
